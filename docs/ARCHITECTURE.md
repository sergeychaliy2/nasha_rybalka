# Архитектура «Наша Рыбалка»

Чистая, feature‑first архитектура на Flutter. Цель — расширяемость (весь мир,
сотни рыб/снастей), тестируемость доменной логики и независимость UI от
источников данных. Сейчас всё локально; при появлении сервера меняются только
реализации репозиториев.

## Слои и направление зависимостей

```
presentation  →  domain  ←  data
   (UI)          (ядро)     (источники)
```

- **domain** — сердце. Чистый Dart, без Flutter. Сущности, value objects,
  интерфейсы репозиториев, доменные сервисы (алгоритм поклёвки, экономика,
  уровни). Ни на что не зависит.
- **data** — реализации репозиториев и источники (сид‑контент, `SharedPreferences`).
  Зависит от `domain` (реализует его интерфейсы).
- **presentation** — экраны/виджеты/контроллеры (Riverpod). Зависит от `domain`,
  не знает о `data` напрямую (получает через провайдеры‑границы).

Зависимости всегда направлены **внутрь**, к `domain`. UI и данные не знают друг о
друге — связаны только через интерфейсы и Riverpod‑провайдеры.

## Структура каталогов

```
lib/
  app/                  # композиция приложения
    providers.dart      # Riverpod: репозитории, сервисы, контроллеры (DI‑граница)
    theme/              # тёмная «мужская» тема
  core/                 # общие утилиты (Result, расширения) — по мере роста
  domain/
    entities/           # World, Country, FishingLocation, FishSpecies, Gear, Player…
    value_objects/      # Money/CurrencyType, Weight, перечисления механик
    repositories/       # ИНТЕРФЕЙСЫ: ContentRepository, PlayerRepository
    services/           # BiteCalculator, EconomyService, LevelingService (чистые)
  data/
    seed/               # SeedContent — встроенный контент (Dart)
    repositories/       # SeedContentRepository, LocalPlayerRepository (impl)
    sources/            # внешние источники (на будущее: JSON/HTTP)
  features/             # экраны по фичам (world_map, location, shop, bestiary…)
  demo/                 # ВРЕМЕННО: прототип сцены ловли (Canvas + Flame) для выбора рендера
  shared/               # переиспользуемые виджеты
```

## Ключевые решения

- **Состояние — Riverpod 3.** Провайдеры в `app/providers.dart` — единая точка
  сборки зависимостей (DI). `PlayerController` (`AsyncNotifier`) грузит сейв,
  мутирует профиль и авто‑персистит.
- **Контент — данные, не код движка.** `ContentRepository` отдаёт мир/рыб/снасти.
  Сейчас источник — `SeedContent` (типобезопасный Dart). Переход на JSON‑ассеты
  или сервер = новая реализация интерфейса, без правок UI/домена.
- **Сейв — локально.** `LocalPlayerRepository` поверх `SharedPreferences` (JSON
  снимок `Player`). Заменяется на сетевой репозиторий «как есть».
- **Доменные сервисы — чистые и тестируемые.** `BiteCalculator`, `EconomyService`,
  `LevelingService` не зависят от Flutter; RNG инъектируется → детерминированные
  юнит‑тесты (`test/`).
- **Деньги/вес — value objects.** `Money`/`Weight` инкапсулируют правила
  (неотрицательность, форматирование, арифметику), исключая «магические int».
- **Расширяемость валют.** `CurrencyType` — единственная точка добавления новой
  валюты; кошелёк/магазин подхватывают её без переписывания (хук под особую ветку).

## Рендер сцены ловли

Геометрия и отрисовка снасти вынесены в `demo/rod_geometry.dart` (чистые функции
над `Canvas`) и переиспользуются **обоими** прототипами — Canvas (`CustomPainter`)
и Flame (`Component.render`). Это гарантирует идентичный вид удилища/лески/поплавка
и делает сравнение рендеров честным. После выбора подхода победивший вариант
переедет из `demo/` в `features/fishing/` поверх доменных моделей и провайдеров.

## Тестирование

- `test/` — юнит‑тесты доменных сервисов (поклёвка, экономика, уровни) и виджет‑
  smoke‑тест. Доменные тесты не требуют Flutter‑окружения и быстры.
